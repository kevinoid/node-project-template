# Security Policy

## Supported Versions

This project currently only supports the most recently released version and
does not provide backports.  Please ensure any reports apply to this version.


## Reporting a Vulnerability

Please report security-sensitive issues via [GitHub private vulnerability
reporting](https://docs.github.com/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).


## Timeline

We aim to respond promptly, provide an assessment within one week, release a
fix within one month, and publicly disclose the issue when the fix is
released.

Please keep in mind that this project is maintained by a tiny team on a
best-effort basis and we may not always be able to meet the above timeline.


## Disclosure Policy

We aim to follow standard [Coordinated Vulnerability
Disclosure](https://www.sei.cmu.edu/documents/1945/2017_003_001_503340.pdf)
practices.  Please give us the time described above to investigate and fix the
issue before disclosing it publicly.  When a fix is released, we will publish
a security advisory and credit reporters in the advisory and release notes,
unless asked not to.

If we do not respond or fix the issue within the timeline above, you are free
to disclose it publicly.  We would appreciate a heads-up before you do.


## Appreciation

We appreciate responsible security research conducted in good-faith and the
benefits it brings for our users and our industry.  We welcome security
reports and pledge to handle them with consideration, and to do what we can to
publicly acknowledge and show our appreciation for the effort and achievements
they represent.
